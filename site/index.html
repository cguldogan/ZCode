How it differs from ZCode

  • Local models first: a LiteLLM provider preset (http://localhost:4000/v1) with “Load models” discovery from any OpenAI-compatible server.
  • No vendor accounts: Z.ai/BigModel login, coding plans and their providers are removed; zcode login/logout are disabled.
  • No China egress: every process blocks connections to China-operated services (the vendor, Alibaba Cloud, Tencent, ByteDance Lark, Chinese model APIs, any .cn host) before DNS.
  • No telemetry, no remote control: analytics reporting is off at build time; no auto-update, forced update or remote provider configuration.
  • TUI extras: /review panel for uncommitted changes, /undo / /redo of the last agent turn's file edits, status line with tokens/s, /exit, real context window, and hold-to-delete-faster.

Other providers that are not China-operated (OpenAI, Anthropic, xAI, OpenRouter, custom OpenAI-compatible endpoints) remain available if you add them yourself.

Install notes

macOS — unsigned app

Open the DMG and drag ZCode Beyond into Applications. The app is not notarized, so the first launch is blocked: right-click the app → Open → Open. If macOS says the app is damaged, remove the quarantine flag: 

xattr -dr com.apple.quarantine "/Applications/ZCode Beyond.app"
Windows — SmartScreen

The installer is unsigned. When SmartScreen shows “Windows protected your PC”, choose More info → Run anyway.

Linux — AppImage, .deb, .rpm 
chmod +x ZCode-Beyond-linux-x64.AppImage
./ZCode-Beyond-linux-x64.AppImage

# or Debian/Ubuntu
sudo apt install ./ZCode-Beyond-linux-x64.deb

The packages install as zcode-beyond, separate from an official ZCode install.

Terminal CLI

macOS / Linux (replace mac-arm64 with your platform):

curl -fLO https://github.com/__REPO__/releases/download/latest/zcode-beyond-cli-mac-arm64.tar.gz
tar -xzf zcode-beyond-cli-mac-arm64.tar.gz
mkdir -p ~/.local/bin
mv zcode-beyond-cli-mac-arm64/zcode ~/.local/bin/zcode
zcode --help

Make sure ~/.local/bin is on your PATH. If you downloaded the archive with a browser on macOS, clear the quarantine flag once: xattr -d com.apple.quarantine ~/.local/bin/zcode. On Windows, unzip and run zcode.exe.

Node.js build (needs Node.js 24; includes the browser UI via zcode --web): 

mkdir -p ~/.local/share/zcode-beyond
tar -xzf zcode-beyond-cli-node.tar.gz -C ~/.local/share/zcode-beyond
node ~/.local/share/zcode-beyond/zcode/bin/zcode.mjs --web

The command is still called zcode and keeps its data in ~/.zcode, like upstream ZCode; check command -v zcode if you also have the official CLI installed.

Verify a download 
shasum -a 256 -c ZCode-Beyond-mac-arm64.dmg.sha256   # macOS
sha256sum -c ZCode-Beyond-linux-x64.AppImage.sha256  # Linux

LiteLLM quick setup

LiteLLM is a self-hosted, OpenAI-compatible proxy that can sit in front of your local model servers. ZCode Beyond ships a LiteLLM provider template.

  1. Run a LiteLLM proxy for your local models (its default address is http://localhost:4000).
  2. In ZCode Beyond open Settings → Model settings, add a provider and pick LiteLLM. The base URL defaults to http://localhost:4000/v1; change it if your proxy runs elsewhere.
  3. Enter your LiteLLM key. If the proxy runs without authentication, any placeholder (for example sk-local) works — the field cannot be empty.
  4. Save, then click Load models to import the model names from GET /v1/models, or add model names by hand.

“Load models” works for any provider using the OpenAI chat-completions or responses API, so other local OpenAI-compatible servers can be added the same way.
