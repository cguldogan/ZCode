# @zcode/node-repl-host

Shared host for `node_repl`: the JS execution surface (a single `js` tool) and the two domain
bridges (Browser Use, Computer Use) both live here.

## Why it is a standalone package

The host is **shared by official capabilities** and belongs to no single plugin. It used to live
inside `browser-use-plugin`, with these consequences:

- Touching Computer Use required changing the browser-use package;
- The CUA SDK and docs each had a hand-maintained copy inside browser-use;
- `resolveBuiltInNodeReplMcpServers` only looked for the host artifact under browser-use's
  rootPath, so if the browser-use package was missing, CUA could not get the host even when
  CUA itself was enabled.

Registration was already consolidated in the CLI core (`bootstrap/src/app/built-in-node-repl.ts`,
triggered when either `bua` or `cua` is enabled); what was always missing was **artifact
ownership**. This package puts the source code back where it belongs.

## Artifacts are still carried by the plugin packages

`dist/mcp/server.js` and `scripts/computer-use-client.mjs` are listed in the SEA release
manifest (`OFFICIAL_BROWSER_USE_REQUIRED_SEED_PATHS`), so the paths cannot change. Therefore
browser-use's build bundles this package's `src/server.ts`, and CUA's client/docs copies are
generated by build scripts instead of being hand-maintained. Moving the artifacts out of the
plugin roots too would require changing both the SEA manifest and bootstrap's hostPackage
resolution, and is a separate step.
